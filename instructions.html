1. Краткое описание и цель

Цель: собрать воспроизводимые аннотации растений, покрывающие все части (корень, стебель, лист, бутон, цветок, плод, семена, повреждения) и все стадии роста. Важный контекст — условия выращивания (система питания, спектр освещения), которые включаются в метаданные и учитываются при разметке.

2. Обязательные метаданные для каждого изображения

Каждое изображение обязательно снабжать метаданными (примеры ниже). На мобильном устройстве удобно использовать JSON-форму в текстовом редакторе или заметках.

ПолеОписание
image_idУникальный идентификатор
acquisition_datetimeВремя съёмки (ISO 8601)
camera_idИД камеры
imaging_modeRGB / multispectral / hyperspectral
spectral_profileСписок каналов и относительные значения
lighting_descriptionТип ламп, PAR, R:FR, blue_frac
nutrient_systemsoil / hydroponics / aeroponics + параметры
growth_stageseedling / vegetative / flowering / fruiting / senescence
Подсказка: на смартфоне удобно сначала заполнить метаданные в Notes (или в Google Forms), затем скопировать JSON в поле metadata при экспорте аннотации.

3. Таксономия: категории и атрибуты

Рекомендуемая базовая таксономия (адаптируйте под вид):

  • leaf, stem, flower, fruit, bud, root, disease_spot

Атрибуты: growth_stage, health_status, occluded, visibility, age_days.

4. Правила разметки (интерактивно и кратко)

Выделяем объекты минимальным bbox; для сложных контуров используем polygon/mask. Обязательно указывать occluded=true при перекрытии >30%.

Как поступать в мобильном интерфейсе

  1. Увеличьте изображение пальцами, чтобы точно поставить точки bbox/полигон;
  2. Используйте маску для пятен болезней — это даст точную сегментацию;
  3. Заполняйте атрибуты после завершения рисования, чтобы не потерять фокус.

5. Условия выращивания — что важно учитывать

Записывайте системные параметры: lighting.system, lighting.metrics (PAR, PPFD, R:FR), nutrient.system (EC, pH) — это поможет фильтровать данные по сценарию обучения.

6. Экспорт: формат COCO + metadata

Экспортируем COCO JSON и добавляем images[].metadata с полями lighting и nutrient_system. Это существенно упрощает downstream-фильтрацию.

7. Спорные случаи и быстрые правила

  • Частично видимые объекты: аннотировать если ≥25% видно.
  • Отражения и блики: не аннотировать как объект; пометить notes: "specular_glare".
  • Цветовые сдвиги из-за LED: помечать color_shift_due_to_light=true.

8. Контроль качества — кратко

Используйте gold set (5–10% корпусa). На мобильном удобно просматривать gold-примеры в отдельной папке и сверять параметры.

9. Пошаговая инструкция для аннотатора (короткая, для мобильного)

  1. Откройте задачу в приложении / Label Studio мобильный браузер.
  2. Проверьте metadata (lighting, nutrient_system, growth_stage).
  3. Увеличьте изображение и нарисуйте bbox или polygon.
  4. Заполните атрибуты: growth_stage, occluded, health_status.
  5. Добавьте комментарий при сомнении и пометьте needs_expert_review.
  6. Сохраните и закройте задачу.

10. Шаблоны скриптов (короткие инструкции для локальной валидации)

На телефоне можно запускать проверки через терминал на ноутбуке; сохраните JSON и выполните python scripts/validate_annotations.py на ПК. Скрипты и примеры сохранены в основном HTML-документе.
