1. Краткое описание и цель

Цель: собрать воспроизводимые аннотации растений, покрывающие все части (корень, стебель, лист, бутон, цветок, плод, семена, повреждения) и все стадии роста. Важный контекст — условия выращивания (система питания, спектр освещения), которые включаются в метаданные и учитываются при разметке.

2. Обязательные метаданные для каждого изображения

Каждое изображение обязательно снабжать метаданными (примеры ниже). На мобильном устройстве удобно использовать JSON-форму в текстовом редакторе или заметках.

Подсказка: на смартфоне удобно сначала заполнить метаданные в Notes (или в Google Forms), затем скопировать JSON в поле metadata при экспорте аннотации.

3. Таксономия: категории и атрибуты

Рекомендуемая базовая таксономия (адаптируйте под вид):

  • leaf, stem, flower, fruit, bud, root, disease_spot

Атрибуты: growth_stage, health_status, occluded, visibility, age_days.

4. Правила разметки (интерактивно и кратко)

Выделяем объекты минимальным bbox; для сложных контуров используем polygon/mask. Обязательно указывать occluded=true при перекрытии >30%.

Как поступать в мобильном интерфейсе

  1. Увеличьте изображение пальцами, чтобы точно поставить точки bbox/полигон;
  2. Используйте маску для пятен болезней — это даст точную сегментацию;
  3. Заполняйте атрибуты после завершения рисования, чтобы не потерять фокус.

5. Условия выращивания — что важно учитывать

Записывайте системные параметры: lighting.system, lighting.metrics (PAR, PPFD, R:FR), nutrient.system (EC, pH) — это поможет фильтровать данные по сценарию обучения.

6. Экспорт: формат COCO + metadata

Экспортируем COCO JSON и добавляем images[].metadata с полями lighting и nutrient_system. Это существенно упрощает downstream-фильтрацию.

7. Спорные случаи и быстрые правила

  • Частично видимые объекты: аннотировать если ≥25% видно.
  • Отражения и блики: не аннотировать как объект; пометить notes: "specular_glare".
  • Цветовые сдвиги из-за LED: помечать color_shift_due_to_light=true.

8. Контроль качества — кратко

Используйте gold set (5–10% корпусa). На мобильном удобно просматривать gold-примеры в отдельной папке и сверять параметры.

9. Пошаговая инструкция для аннотатора (короткая, для мобильного)

  1. Откройте задачу в приложении / Label Studio мобильный браузер.
  2. Проверьте metadata (lighting, nutrient_system, growth_stage).
  3. Увеличьте изображение и нарисуйте bbox или polygon.
  4. Заполните атрибуты: growth_stage, occluded, health_status.
  5. Добавьте комментарий при сомнении и пометьте needs_expert_review.
  6. Сохраните и закройте задачу.

10. Шаблоны скриптов (короткие инструкции для локальной валидации)

На телефоне можно запускать проверки через терминал на ноутбуке; сохраните JSON и выполните python scripts/validate_annotations.py на ПК. Скрипты и примеры сохранены в основном HTML-документе.

11. Таблицы: количество размеченных изображений и примерная итоговая точность

Приведённые оценки — эмпирические ориентиры. Фактическая точность зависит от сложности задачи, однородности данных, качества разметки, архитектуры модели и augmentation. Значения — ожидаемый диапазон для современных моделей (2023–2025) при правильной валидации.

12. Как оценивается качество полученных датасетов — подробности

Качество датасета оценивается двумя основными направлениями: внешняя оценка модели (как хорошо обученная модель работает на валидационных и тестовых данных) и внутренняя оценка разметки (согласованность разметки и её корректность).

12.1 Внешняя оценка: метрики для моделей

  • Classification: accuracy, precision, recall, F1 (macro/micro), ROC-AUC (для бинарных/многоклассовых задач переиспользуйте AUC per class).
  • Object detection: mAP@0.5, mAP@[0.5:0.95] (COCO), per-class AP, precision-recall curves, average recall.
  • Segmentation: mean IoU, Dice / F1-score for masks, boundary F1 (если важны границы).
  • Keypoints: PCK (percentage of correct keypoints), OKS (Object Keypoint Similarity) и среднее по порогам.
  • Calibration: проверка того, насколько расчетные вероятности модели соответствуют реальным (reliability diagrams, expected calibration error).

12.2 Внутренняя оценка: качество разметки

Сюда входят метрики и процедуры, описанные ниже.

Inter-Annotator Agreement (IAA)

IAA измеряет согласованность между разными аннотаторами. Примеры метрик:

  • Для классификации: Cohen's kappa, Fleiss' kappa, Jaccard.
  • Для bbox: средний IoU между парами аннотаторов, F1@IoU0.5 (считаем TP/FP/FN, как в compute_iaa.py).
  • Для масок: mean IoU между аннотациями, Dice coefficient.

Gold set accuracy

Измеряется как доля совпадений аннотатора с заранее подготовленным экспертным эталоном (gold). Используется для отбора аннотаторов и мониторинга drift.

Review and escalation workflow

  1. Annotator размечает — вставляются скрытые gold-задачи (5–10%).
  2. Peer-review: ревьюит другой аннотатора — возвращает на доработку при несоответствии.
  3. Expert-review: спорные кейсы позже проверяются экспертом; их результаты обновляют gold и spec.

Статистическая значимость

При сравнении моделей/версий датасета важно оценивать статистическую значимость разницы (conf intervals, bootstrap). Простая разница в mAP 0.02 может быть незначимой на малых тестовых выборках.

Bias & coverage analysis

Проверяйте распределение по ключевым осям: вид растения, стадия роста, спектр освещения, система питания, география, камеры. Низкое покрытие по одной оси (например, мало снимков с UV) приводит к плохой генерализации.

13 Практическая процедура оценки качества датасета (шаги)

  1. Разбейте данные на: train / val / test по принципу "plant-aware" (например, не допускать, чтобы снимки одного растения были в train и test одновременно).
  2. Определите gold set — экспертно размеченные 5–10% для контроля качества и отбора аннотаторов.
  3. Запустите парное размечание на 5–10% изображений для расчёта IAA.
  4. Соберите метрики (mAP, IoU, F1) на validation и test — по классам и в сумме.
  5. Проведите error analysis — соберите топ-50 самых частых ошибок и разбейте по типам (occlusion, small object, illumination, wrong label, boundary issues).
  6. Итерация spec — исправьте правила, добавьте примеры, обновите gold и проведите пересмотр аннотаторов.
  7. Проверка стабильности — re-evaluate после каждой крупной партии разметки; используйте bootstrap для CI.

13.1 Комментарии и рекомендации (от автора инструкции)

Ниже — практические советы, основанные на опыте работы с crop/plant datasets.

  • Качество важнее количества. Лучше 10k аккуратных аннотаций чем 100k шумных. Инвестируйте в gold и QA-процессы.
  • Предразметка + правка — самый экономичный путь. Даже простая предразметка от слабой модели сокращает труд в 3–5x.
  • Разнообразие освещения и камер критично: включайте снимки с разными PAR, R:FR, наличием/отсутствием UV — это даст модели инвариантность к свету.
  • Контролируйте class balance. Для редких классов используйте targeted sampling и augmentation (photometric, geometric, spectral shifts).
  • Регулярная ревизия spec. Спорные кейсы должны попадать в backlog и сразу правиться в spec — это улучшает IAA со временем.
  • Метаданные — ваша сила. Хранение lighting/nutrient info позволяет делать условные модели (например, train только на LED scenes или fine-tune per-spectrum).
  • Автоматизированные проверки. Запускайте validate_annotations.py в CI перед принятием любой партии: bbox-выреза, дубли, пустые категории, совпадение spec_version.
  • Мониторинг в продакшене. Слежение за FN/FP после деплоя показывает, какие данные нужно снова разметить (feedback loop).
